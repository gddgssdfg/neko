# 2026-10-23 续改记录（v0.2.4）

本次延续未提交的 v0.2.4 视觉/存储更新，收录分区抚摸已有开发，并集中修复调度器和配置边界问题。

## 调度器

旧版可复现：排期 40 天后的任务立即执行（double 毫秒先强转 int 溢出）；Dispose 后仍能新增任务；一次性回调完成后句柄继续处于活跃状态，且取消任务留在宿主集合内。

改为：

- 毫秒先限幅再转整数，远期日期按有界间隔重新排期，最终回调前再次检查目标日期；UTC 输入转换为本地时间。
- 注册、启动与关闭快照使用同一把宿主锁；释放后拒绝新增任务，停止快照内的全部定时器。
- 一次性任务在成功或异常后自动释放，主动取消后也移出句柄集合，释放底层 Timer 及取消回调对宿主的引用。
- 保留周期任务异常隔离和连续五次失败熔断机制。Dispose 不等待已经开始执行的回调，保持原有边界。

回归覆盖远期任务、UTC 取消、异常单次任务、24 轮注册与关闭竞争、完成/取消后的集合清理，以及原 UiProbe 的四线程 × 125 次回调。旧测试对内部 List/ICollection 的假设改为枚举实际集合，并把「一次性任务永久活跃」断言更新为「恰好执行一次后释放」。

## 配置数据保护

修复前三个回归用例均能复现失败：

1. 文件内容为 JSON null，Load 返回默认值却没有保存原文件。
2. 显式 null 热键/菜单字段仍能通过反序列化，留给后续 UI 解引用；缩放和透明度也未在读取时约束。
3. 并发 Save 使用同一份 .tmp 文件，相互覆盖或消费对方临时文件，产生真实写入错误。

现在将 null 根作为无效配置隔离备份；逐字段恢复空对象并约束尺寸，保留其他配置和未知扩展字段；读取与保存事务串行化，临时内容在替换前刷新到磁盘。

保留原有同步 Save API、文件被短暂占用时的重试，以及最终失败保留 .tmp 的恢复策略。同步重试仍可能阻塞 UI，后台保存队列留待单独设计，避免改变退出时的持久化语义。
