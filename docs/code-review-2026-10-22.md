# Neko 代码审查与视觉更新

审查日期：2026-10-22；2026-10-23 继续修复。代码版本为 0.2.4，尚未创建安装包或发布标签；续改记录见 `docs/continuation-2026-10-23.md`。

## 范围与结论

本轮以宿主启动、配置/插件存储、插件加载与生命周期、渲染计时、设置页主题、素材编译和本地检查脚本为重点，结合既有测试验证。没有逐行穷尽全部业务插件，也没有执行联网 AI 咨询或生成新的安装包。

四层架构清晰，插件加载/卸载已有较充分的防回归覆盖。本轮优先处理实际可复现的数据保护、异常路径和视觉一致性问题，保留原有皮肤与进入本轮之前的分区抚摸开发改动。

## 已修复

| 级别 | 问题 | 改进与验证 |
|---|---|---|
| P1 | API Key 加密失败会静默退回明文 | 加密不可用时抛出加密异常；档案保存透传该异常，设置页明确提示并保留旧存档。正常 DPAPI 往返由 LoaderTest 验证。 |
| P1 | 插件 JSON 数据直接覆盖，异常可能留下半截文件 | 先序列化，再以同目录唯一临时文件写入并刷新，最后替换；同实例读写串行化。故障注入验证序列化失败、目标被锁和并发读写。 |
| P1 | 插件存储 key 可拼接目录路径或 NTFS 数据流 | 所有入口统一验证 key 是单个合法文件名；验证读、写、删、Contains 均拒绝越界键。此改动不是进程级安全沙箱。 |
| P2 | 动画先转 int 再限幅，超长间隔可溢出并留下积压 | 浮点整数部分先取模，再安全转换；验证超 Int32 帧数间隔及后续正常推进。 |
| P2 | 浅色主题混用深色按钮/输入框/滚动条 | 控件使用宿主色板；SDK 标准插件颜色适配当前主题，保留插件自定义颜色和绑定。 |
| P2 | Windows CI 强制依赖固定 Bash 与 PATH 中的 Python | 原生 Windows 默认直接调用 dotnet，将正在执行脚本的 Python 路径传入构建。 |
| P2 | README/隐私说明遗漏默认后台版本检查 | 根据 UpdateService 与 App 启动代码补充 Gitee 查询的时机、请求范围和关闭入口。 |
| P3 | 切图反复以 alpha 作遮罩，透明边缘反复衰减；水平微动参数未生效 | 使用 alpha_composite，应用 dx，允许指定透明间隙中的切分坐标。只重新编译新皮肤，旧素材未重建。 |

## 视觉更新

- 设置页采用暖纸浅色与炭灰深色，统一导航符号、品牌插画、字号、圆角与留白。窗口适配当前工作区尺寸。
- 导航和开关可通过键盘聚焦并按 Enter/Space 操作；其他原有 Border 按钮尚未全面改为语义化 Button。
- 新增「琥珀 · 手绘橘猫」可选皮肤，九状态各四帧。使用内置 image_gen；原画与提示词在 `neko-assets/reference/amber/`，运行资源在 `neko-assets/amber/`。
- 新增可选 `skin.json.pixelArt`，缺省 true 保持旧皮肤最近邻行为，新皮肤 false 使用平滑缩放。
- 新皮肤当前使用姿态原画加微动，没有完整的逐帧步态或独立眼球层。
- 实际 WPF 页面截图保存在本机 `_eval/visual-review/`，包含六个设置栏目的深浅两套共十二张图片；可用 ReliabilityProbe 的 `--capture` 参数重新导出。

## 建议后续推进

1. **调度器边界（2026-10-23 已修复）**：远期任务分段等待，关闭后拒绝新增任务，单次/取消句柄自动清理；补充了远期、取消、异常与并发关闭测试。
2. **配置写入**：`ConfigManager.Save` 仍同步执行重试睡眠，失败路径可能阻塞 UI 约 240ms；可引入统一写入队列，兼顾合并保存、退出刷新和失败提示。
3. **UI 可访问性与国际化**：逐步把自绘 Border 按钮迁移到真正的 Button/ToggleButton，补齐自动化语义、焦点外观和剩余中文文案；插件独立弹窗仍沿用各自样式。
4. **发布验证**：正式交付前重新测量 Release 的冷启动/内存/体积、打包 MSI，并检查运行产物是否含 amber；更新仓库的公开可访问性需要单独核实，本轮没有修改远端设置。

复现命令：

```powershell
python tools/ci.py
dotnet run --project tests/ReliabilityProbe -- --capture _eval/visual-review
```

若本机 `python` 指向不可执行的 Windows Store 别名，请使用实际 Python 路径运行脚本；CI 会把该解释器自动传给 MSBuild 的 PythonExe。
