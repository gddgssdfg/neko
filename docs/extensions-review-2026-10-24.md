# 系统、插件与皮肤接入审查（v0.2.7）

## 范围

检查了系统退出与延迟初始化、插件发现/解析/信任/加载/启停/资源回收、设置页、皮肤注册/图片解码/切片/切换/构建部署，以及内置系统信息、天气等功能代码。18 个内置插件全部参加既有加载、卸载和 ALC 回收测试；没有穷尽所有插件每个交互分支，也未执行真实天气查询、付费 AI 咨询或生成安装器。

## 已改进

| 问题 | 结果 |
|---|---|
| 插件页只列已加载实例，禁用后重启就无法重新启用 | 独立读取已安装清单；禁用、失败插件仍可操作，新增刷新、打开目录和错误提示 |
| 新插件声明错误却缺少直接诊断 | 检查 API 版本、整数类型与范围、权限数组和未知 token；入口必须为本目录内的相对 DLL，入口类 Id 和 API 主版本也需匹配 |
| 重复加载及重复 Dispose | 排除已加载 ID；卸载及释放幂等；正常插件 ID 比较不区分大小写 |
| OnLoad 中途失败泄漏调度器，忘记退订可能继续收到事件 | 宿主持有每插件事件作用域与调度器；失败回滚、禁用、退出均释放，成功重试清除旧错误 |
| 传给宿主的数据根与插件实际写入位置不一致 | PluginDataDir 和 JSON 存储均使用传入的数据根 |
| 启停通知订阅者抛出异常可能把成功启用误判为失败 | 单独隔离通知异常，不中断其他订阅者或改变插件实际启停结果 |
| 快速退出后后台初始化重新创建资源，游戏轮询未停止 | 防重复启动；已排队的插件、镜像、闲聊和菜单初始化检查窗口生命周期，Dispose 停止游戏轮询 |
| PNG 损坏、切片越界可能中断皮肤加载 | 每状态隔离解码和切片错误，独立帧尺寸需一致；损坏眼层与阴影可跳过 |
| 待机不可用造成空白或配置仍指向坏皮肤 | 尝试默认 pixel，并保存真实皮肤 ID；两套资源都不存在时只能保活与记录日志 |
| 重选同一皮肤不能加载替换后的素材 | 新增显式刷新入口，同时保留原 SetSkin(string) 调用兼容性 |
| 眼眶遮罩缓存跨皮肤沿用 | 更换图集时清空缓存，避免眼睛被上一套皮肤的遮罩裁切 |
| 新随包皮肤必须同步多个 csproj | 共用 build/RuntimeAssets.props 自动收集运行素材，保留相对目录并排除原画、预览和模型源文件 |
| 系统信息 CPU 读数偏高、盘符固定写 C | 按 kernel 已含 idle 的接口语义计算；磁盘标签使用实际盘名，系统调用失败不再使用无效数据 |
| 三日天气只显示两天，区域格式把经纬度变为逗号小数，未知城市套用默认天气 | 输出三天；坐标采用固定小数格式；未知城市明确提示；卸载后的查询不恢复 HttpClient 或继续播报 |

CPU 时间语义依据：[Microsoft GetSystemTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes)。

## 接入方式

插件：将完整插件目录放到程序旁 `plugins/<id>/`，在设置中刷新列表并启用。更新已加载插件前先禁用，替换文件后重新启用。发现清单不会执行插件；启用仍走信任检查。

皮肤：放到程序旁 `neko-assets/<id>/`，提供清单与 PNG，在设置中刷新皮肤后选择。作者替换当前皮肤素材后可直接刷新，无需重启。源码随包皮肤由共用构建规则处理。

详细约定见 [插件开发指南](plugin-development-guide.md) 和 [皮肤开发指南](skin-development-guide.md)。

## 后续可推进

- 配置保存仍有同步重试；可在独立改动中引入合并保存队列，并验证退出刷新和失败提示。
- 第三方插件自行创建的任务、窗口和网络请求仍需作者主动取消；本轮的事件/定时器作用域不是进程沙箱。
- 内置插件各自构造的输入框与弹窗仍有主题和可访问性差异；本轮截图中部分插件专有控件尚未统一。
- 没有增加 ZIP 安装器、插件市场或自动升级渠道，避免把接入稳定性修复与新的分发机制混在一起。
